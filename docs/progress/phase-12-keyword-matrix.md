# 阶段 12:关键词矩阵与页面分工

日期:2026-08-05
版本:1.2.0

## 输入

两份外部文档:

- 《2026 年整站 SEO 关键词优先级清单》—— P0 到 P10 的关键词分层与页面建议
- 《2026 机场网站 SEO＋GEO 长尾问题库》—— 约 1800 行、上千个长尾问题

目标:把前者变成页面分工,把后者变成内容结构,形成覆盖 SEO 与 GEO 的矩阵内容。

## 首先识别出的冲突

关键词清单假设的是一个**排行榜商业站**:首页 H1 定为「2026 机场推荐与稳定机场排行榜」,P1 是排行榜页,P2 是便宜机场名单与优惠码页,P6 是品牌评测页。

这些页面的内容主体都是**具体哪几家机场**。而本站目前:

- `src/content/providers/` 下 3 个档案全部是虚构示例(`dataStatus: sample` + `noindex`);
- 没有任何经过核验的真实服务数据;
- 也没有实测基建(测速环境、长期观察记录)。

用虚构数据填充这些页面会同时触发三个反向效果:Google helpful content 系统针对的正是这类「为搜索引擎而非用户制作」的名单页;Bing 对无法核实的商业排名有对应质量信号;AI 搜索不会采纳无法溯源的排名结论,反而降低整站被引用的概率。**与提升排名的目标直接冲突。**

### 采取的方案

把矩阵的**骨架**与**判断方法层**全部建满,把**具体名单层**留成结构化占位:

- 新建 `ProviderListPending` 组件:说明名单上线后会展示哪些字段、按什么标准筛选,并把读者导向自行判断的方法;
- `picks` schema 增加 `providerListStatus` 字段(`ready` / `pending`),真实数据到位后改一个值即可;
- URL、title、内链结构全部按最终形态建好,追加名单时不需要新建页面,已积累权重全部保留。

## 交付内容

### 1. `docs/keyword-matrix.md`(核心交付物)

- 各优先级层级到具体 URL 的映射表
- 长尾问题库到内容结构的转换规则(章节主问题 → H1;核心 5–10 问 → H2;延伸问题 → frontmatter `faq`;GEO 问题四类分别落到 `summary` / 对比表 / 「为什么」小节 / 有序步骤)
- GEO 内容格式要求与实现方式对照
- 年份词处理:不建重复 URL,通过 title、`updatedAt`、正文年度说明、`reviewedAt` 四处体现
- 避免关键词内耗的检查清单 + 7 组易混淆边界对照

### 2. `picks` 内容集合与 16 个专题页

新集合,URL `/airport/<slug>/`,复用 ArticleLayout 获得完整的 SEO 与 GEO 处理(直接答案、关键结论、目录、FAQ、面包屑、JSON-LD、相关阅读)。

schema 新增:`priority`、`primaryKeyword`、`secondaryKeywords`(2–8)、`longtailKeywords`、`providerListStatus`、`criteria`。

16 页分四组:客户端 4、场景 5、线路与 IP 2、价格套餐 4、选购参考 1。

每页实际产出:主词 1 + 次词 4–5 + 长尾 15–16 + 评估维度 6–7 + FAQ 10–12 + 站内链接 5–7,正文 1400–1760 字。

### 3. 新增组件

- `ProviderListPending.astro` —— 结构化占位
- `CriteriaTable.astro` —— 从 `criteria` 渲染评估维度表
- `PicksGrid.astro` —— 按优先级分组的专题导航(Hub→Spoke 内链层),首页与 `/airport/` 各用一次,`bare` 参数控制是否自带容器

## 内容约束(对全部 16 个专题页强制)

- 不出现任何具体机场品牌名、服务名单、价格表或优惠码
- 不使用「我们推荐 / 我们测试了」——本站尚未做实测,这类表述是虚假的经验声明
- 禁用绝对承诺用语
- 涉及解锁效果时必须写明会随平台策略变化、需要自行验证

`ranking.md` 与 `coupon.md` 在正文中直接说明本站为什么暂不发布名次榜与优惠码清单,并列出将来发布时会遵守的规则。这比留空页或编造更有信息价值。

## 下一阶段

矩阵的骨架已经完整,现在的瓶颈**不再是内容产能,而是数据**。

`docs/keyword-matrix.md` 第七节列出了真实数据就绪后的四步操作。在那之前,继续增加方法类内容的边际收益已经明显下降——P1、P2、P6 三层关键词的搜索意图本质上是「给我一份名单」,方法类内容只能部分满足。

优先级建议:建立真实服务档案 > 建立可复现的测试基建(测速环境与记录规范) > 继续扩展内容。
