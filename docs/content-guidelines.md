# 内容创作规范

## 基本立场

本站是知识博客,不是推广落地页。判断一篇内容合不合格的标准是:**读者看完之后能不能自己做出判断或解决问题**,而不是有没有点击某个链接。

## 语言与语气

中性、专业、教育性。用自然中文表达,直接陈述句为主。

**明确禁止的批量生成痕迹:**

- 每篇使用完全相同的开头结构
- 「随着互联网的发展」「在当今时代」这类空转开场
- 每篇文章段落数量和小标题措辞高度雷同
- 反复解释同一个基础概念(应该链接到术语表)
- 为了关键词密度机械重复词组
- 用大量空泛形容词代替具体信息
- 所有文章的结论完全相同
- 同类文章只替换品牌名和价格

**禁止的绝对承诺:**

「绝对最好」「永远稳定」「100% 解锁」「零风险」「保证不掉线」。`audit:content` 会扫描正文中的这类用语并给出警告。

涉及不确定信息时,写明不确定性和影响因素,而不是回避或含糊带过。

## 结构按搜索意图变化

不同类型的文章结构不同,不套同一个模板。

**故障排查文章**强调排查步骤:

```
症状判断 → 最常见原因 → 一分钟快速检查 → 按顺序排查
→ 不同设备处理差异 → 如何验证已恢复 → 仍未解决时收集哪些信息
```

排查顺序遵循固定的层级,从外到内:

```
网络状态 → 系统时间 → 客户端状态 → 订阅状态 → 节点状态
→ DNS → IPv6 → 路由规则 → 防火墙 → 线路问题
```

不要一上来就建议重装客户端。重装是掩盖问题而不是定位问题,而且用户重装后往往连原来的现象都无法复现了。

**选择类文章**强调判断标准:参数怎么读、什么情况选什么、常见误区、什么时候这个参数不重要。

**协议类文章**强调定义、区别和适用场景:一句话定义 → 工作方式(通俗解释)→ 关键区别对比表 → 各自适用场景 → 常见误解。

**教程类文章**强调可复现的步骤:适用平台与版本 → 准备事项 → 安装来源 → 配置步骤 → 订阅导入 → 模式选择 → 如何测试 → 常见错误 → 如何退出并恢复系统设置 → 安全注意事项。

**评测类文章**强调信息状态而非评分:信息档案 → 已核实项 → 待核实项 → 优点 → 局限 → 适合谁 → 不适合谁 → 选择结论。在没有完整测试依据时不使用精确评分。

## 每篇文章尽量包含

- 80 至 160 字的直接答案(`summary` 字段)
- 3 到 6 条关键结论(`keyTakeaways` 字段)
- 清晰的 H2/H3 层级,不跳级
- 实用步骤(有序列表)
- 至少一个表格或清单
- 明确的适用与不适用情况
- 常见误区
- 3 到 5 条 FAQ
- 3 到 4 条相关文章
- 更新日期
- 参考来源(有外部依据时)

长度按搜索意图决定,不机械要求统一字数。支柱内容可以较长;单一故障问题优先做到直接、清晰、完整,不为凑字数注水。

## 内部链接

正文中 3 到 7 个站内链接,使用绝对路径。要求:

- 锚文本自然,读起来像句子的一部分,不是硬塞的关键词
- 同一篇文章内不重复使用完全相同的锚文本
- 专业术语第一次出现时链接到 `/glossary/` 对应词条
- 只链接实际存在的页面(`audit:links` 会检查)

## 数据状态与真实性

服务档案、评测、测速、套餐和对比数据必须标注状态:

| 状态 | 含义 | 索引 |
| --- | --- | --- |
| `verified` | 已核实 | index |
| `reference` | 参考数据 | index |
| `sample` | 示例数据 | **必须 noindex** |
| `pending` | 等待补充 | 视情况 |
| `outdated` | 需重新核验 | index(页面显示提示) |

**红线:**

- 不把示例数据伪装成真实测试结果
- 不生成虚假的真实用户身份
- 不把模拟评价描述为已验证用户反馈
- 不对无法确认的信息作绝对承诺
- 不虚构 AggregateRating 或用户评分

测速或对比模块使用参考数据时,必须显示:

> 以下数据用于展示内容结构或提供一般参考。实际结果会受到设备、网络、地区、时间和线路状态影响。

`TestEnvironment` 组件已内置这段说明。

所有数据模块可独立替换,套餐、价格、测速数字和服务状态不硬编码在多个组件中——它们只存在于 `src/content/providers/` 下的 frontmatter 里。

## 推广内容

含推广关系的页面必须显示推广披露(`AffiliateDisclosure` 组件),评测页和对比页默认显示。推广内容与普通内容在视觉上要可区分。推广关系不改变内容结论。

推广链接使用 `rel="nofollow sponsored"`。

## 术语统一

服务名称、客户端名称、协议名称和线路名称全站保持统一拼写:

Clash、Shadowrocket、v2rayN、sing-box、Surge、Quantumult X、Shadowsocks、Trojan、VLESS、Hysteria 2、IEPL、IPLC。

新增术语时先在 `src/content/glossary/` 建立词条,再在文章中链接。

## 图片

目前站内不使用截图。如需添加,每张图片必须有:有意义的英文文件名、`width`、`height`、`alt`、`loading`、`decoding`、合理格式(WebP 或 AVIF)。首屏重要图片不使用懒加载。没有真实截图时使用明确标注的占位组件,不显示破损图片。

## 提交前

```bash
npm run validate
```

内容检查会拦截:必填字段缺失、无效日期、`related` 指向不存在的内容、`author` 指向不存在的作者档案、`sample` 未设 noindex、正文过短。
