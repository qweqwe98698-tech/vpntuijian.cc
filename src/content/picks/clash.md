## Clash 对机场提出的额外要求

多数客户端只要拿到节点信息就能连,Clash 不同——它读取的是一份完整的 YAML 配置文件,里面除了节点,还包含策略组、分流规则、DNS 设置这些结构化内容。这意味着机场交付给你的不只是"几个节点",而是一份配置的组装结果。配置组装得好不好,直接决定你导入之后是开箱可用,还是要花一晚上自己改 YAML。

这也是为什么同样一家服务,在别的客户端上口碑不错,到了 Clash 上却被抱怨"用不了"。问题往往不出在节点质量,而出在交付格式:面板里只有一条通用的 Base64 订阅,复制进 Clash 的配置页,解析结果是空的。

还有一层是内核。[Clash](/glossary/clash/) 早已不是单一软件,现在桌面端的 Verge 系客户端、Android 上的 Meta 客户端,底层跑的都是 mihomo 内核,它比原版多支持一批较新的协议。如果一家机场主推 Hysteria 2 或 VLESS Reality,而你手上是老版本客户端,订阅能下载下来,节点却大半点不亮。协议是否被支持,是买之前就该对上的信息,不是买完再试。

## 下单前值得花五分钟做的确认

1. 打开机场的用户面板或试用页面,找订阅区域,看是否存在**单独标注 Clash 的复制按钮**。如果只有一条"通用订阅",说明你需要额外做格式转换,把这项成本算进去。
2. 拿到试用订阅后,先在浏览器里直接打开这条链接。返回内容如果是 `proxies:`、`proxy-groups:` 这类 YAML 字段开头,格式基本对了;返回一长串没有换行的乱码,那是 Base64 通用格式。
3. 在返回的配置文本里搜索协议关键字,确认里面的 `type` 值(如 `ss`、`trojan`、`vless`、`hysteria2`)你所用的客户端版本都认识。不确定的话,优先选内核较新的客户端。
4. 导入后不要只看节点列表,翻到策略组页面,看是否已经有"国内直连""流媒体""广告拦截"这类分组。有,说明规则分流随订阅下发;没有,你得自己套模板。
5. 如果计划开 [TUN 模式](/glossary/tun-mode/),在试用期内就把它打开跑一次游戏或桌面客户端,验证 UDP 是否可用。这项在试用结束后才发现不行,退款会很麻烦。
6. 最后确认面板能否自助重置订阅链接。这条不影响日常使用,但订阅一旦意外泄露,没有重置入口就只能换账号。

## 容易被忽略的几类兼容性问题

| 现象 | 常见原因 | 规避方式 |
| --- | --- | --- |
| 导入成功但节点列表为空 | 复制的是通用 Base64 订阅,不是 Clash YAML | 回面板选 Clash 专用链接;若面板没有,把转换成本计入选购判断 |
| 部分节点显示但连不上 | 订阅含新协议,当前内核不支持 | 换用基于 mihomo 内核的客户端,或选协议覆盖更保守的订阅 |
| 有节点但所有网站都走代理 | 订阅只给裸节点,未下发分流规则 | 选会下发规则集的服务,或自行套用带规则的配置模板 |
| 策略组里节点匹配错乱 | 节点命名无固定结构,正则规则抓不到 | 观察试用订阅的节点名是否带地区、倍率等统一字段 |
| TUN 模式下游戏或语音不通 | 节点未开放 UDP 转发 | 试用期内实测 TUN 场景,不要只测网页 |
| 换设备后需要另一条链接 | 机场按平台拆分订阅且格式不互通 | 优先选一条 Clash 订阅可跨 Windows / macOS / Android 通用的服务 |

这张表里最值得单独说的是第三行。不下发规则并不等于服务差,有些主打自由配置的服务就是刻意只给节点,让用户自己控制策略。但如果你是第一次用,这类交付方式的上手成本明显更高,选购时要有心理准备。

## Clash 未必是最合适的那一个

Clash 的强项在规则分流和跨平台配置复用,代价是概念多、配置面广。有几种情况下换个客户端反而更省事。

**你只在 iPhone 上用。** iOS 侧的生态另有一套,Clash 系在 App Store 的可用选项有限,直接从 iOS 常用客户端入手更顺,可以先看[小火箭方向的选购要点](/airport/shadowrocket/)。

**你只需要在 Windows 上偶尔连一下。** 如果不涉及复杂分流,只想连上就走,配置更轻的 Windows 客户端上手更快,选购关注点也不一样,详见 [v2rayN 的兼容性判断](/airport/v2rayn/)。

**你的服务主推的协议 Clash 支持不全。** 少数服务把重心放在自研或较冷门的传输方式上,这时官方推荐的客户端通常兼容性最好,硬套 Clash 只会持续掉节点。

**你要配在路由器上。** 家庭网络层的方案与桌面客户端逻辑不同,直接走路由器代理路线更合适。

## 买完发现跑不起来的处理顺序

先别急着申请退款,大部分"用不了"是可修复的配置问题,而且判断成本很低。

第一步,确认订阅本身是否有效——浏览器直接访问链接,看有没有内容返回。第二步,确认格式是否对路,即上文提到的 YAML 与 Base64 之别;这一步失败的处理路径,可以对照[订阅导入失败的排查流程](/troubleshooting/subscription-import-failed/)。第三步,如果节点已加载但全部点不亮,按[全节点超时的分层排查](/troubleshooting/all-nodes-timeout/)走一遍,重点看是不是流量耗尽或订阅到期这类账号侧原因。第四步,若能测出延迟却打不开网页,问题多半在 DNS 或系统代理开关,而不在机场。

如果你是第一次接触 Clash 的配置结构,把[订阅导入与基础配置流程](/clients/clash-subscription-import/)完整走一遍,再回头看上面的判断标准,会清楚很多。真正需要考虑换服务的信号只有一个:订阅格式、协议支持、规则下发这三项里有硬性缺失,且对方明确不提供——这属于交付能力问题,不是你配置得不够仔细。
