## 为什么「延迟低」这个说法本身就不够用

打开任何一个客户端,节点列表旁边都有一列毫秒数。很多人就用这一列做决策:哪个数字小选哪个。然后遇到的情况是,选了个显示 45 毫秒的节点,语音通话还是断断续续;换了个显示 120 毫秒的,反而顺畅。

原因是那个数字只测了一次往返耗时,它回答不了两个更关键的问题:这个数字稳不稳,以及数据包会不会丢。实时场景里,体验好坏由三项共同决定:

- **延迟**决定操作到反馈之间的固定间隔,越低越跟手。它有物理下限,由地理距离和光速决定,任何线路优化都突破不了。
- **抖动**决定卡顿感。延迟从 50 跳到 200 再回到 60,应用层看到的是数据忽快忽慢,语音会断续,画面会顿挫。稳定的 120 通常比波动剧烈的 50 好用。
- **丢包**决定断线和回溯。丢了的包需要重传或直接被丢弃,前者拉高实际延迟,后者造成语音吞字、游戏中人物瞬移。

所以「低延迟机场推荐」这个需求,准确的表述应该是:找一条延迟够低、波动够小、丢包够少的线路。三项缺一,体验都不成立。想细看指标定义可以参考[延迟](/glossary/latency/)和[丢包](/glossary/packet-loss/)的术语说明。

## 一套五分钟能做完的自测流程

1. **确定你的地理下限。** 先看可用节点里离你最近的地区。这个地区的常见延迟量级就是你能达到的最好水平,比它低很多的数字要么是测量方式不同,要么不可靠。
2. **连续测两分钟,而不是一次。** 保持对同一节点持续测试两分钟,记录最小值、最大值和平均值。最大减最小的差值就是抖动的直观体现,这个差值比平均值更有参考意义。
3. **在晚高峰重测一遍。** 同一节点,晚上九点前后再测一次。把两次的抖动差值做对比,劣化幅度小的线路才是真正稳定的。如果高峰期劣化严重,先按[晚高峰掉速的排查路径](/troubleshooting/evening-peak-slow/)确认瓶颈在哪一段。
4. **在真实场景里验证。** 指标合格不等于体验合格。用实际要跑的应用连续跑十分钟,通话是否断续、操作是否跟手,这一步才是最终判据。
5. **控制变量再下结论。** 测试时关掉后台下载、暂停其他设备的大流量占用。带宽被占满会推高排队延迟,这时测出来的数据反映的是你自己的网络,不是节点。

## 常见认知与实际情况

| 常见说法 | 实际情况 |
| --- | --- |
| 「ping 值越低体验越好」 | ping 只反映单次往返,抖动和丢包对实时体验的影响往往更大 |
| 「延迟低说明带宽大」 | 两者独立。低延迟节点可能带宽很小,拖文件时反而慢 |
| 「选最近的地区一定最快」 | 路径可能绕行第三地,实测偶尔会出现更远的地区反而更优 |
| 「专线节点延迟一定更低」 | 专线的优势是波动小,不是数值低。基础延迟由物理距离决定 |
| 「低倍率节点更划算所以高峰期也该用」 | 低倍率节点通常人更多,高峰期排队更严重,稳定性反而更差 |
| 「机场可以替代游戏加速器」 | 两者优化目标不同,通用转发难以覆盖特定游戏服务器的路由优化 |

## 协议选择:弱网环境里的差别

在有线宽带、信号良好的环境下,传输方式带来的差别通常不明显。差别集中出现在弱网:移动数据、公共 Wi-Fi、信号不稳的场景。

基于 TCP 的传输在遇到丢包时会触发重传和拥塞退让,表现为速度骤降后缓慢恢复;基于 UDP 的方案自行处理丢包与拥塞控制,在同样的丢包率下往往能维持更平稳的吞吐,代价是对服务端配置和带宽消耗的要求更高。如果你经常在移动网络下使用实时应用,这类协议值得优先考虑,原理见[相关协议说明](/protocols/hysteria2-explained/)。

另外一个常被忽略的开销是客户端模式。全局接管的 [TUN 模式](/glossary/tun-mode/)处理链路更长,在部分设备上会额外增加几毫秒到十几毫秒。没有全局代理刚需时,规则分流通常是更轻的选择。

## 说清楚边界:哪些需求不该指望机场解决

这一点需要诚实:机场做的是通用跨境流量转发,它不针对某款游戏的服务器做路由优化,也不做协议层的丢包补偿。所以下面这些情况,换机场的收益有限:

- **高强度实时对战游戏。** 这类需求对特定服务器的路由质量要求很高,专用加速工具的优化方向更对口,通用机场只能碰运气。
- **延迟已经接近物理下限。** 如果你到目标地区的延迟已经贴近该距离的理论值,换任何线路都不会有质变。
- **瓶颈在本地。** 无线信号弱、路由器负载高、同一网络下有人在大流量下载——这些换节点都解决不了。
- **只做浏览和看视频。** 这类用途对抖动容忍度高,没必要为低延迟支付溢价,按[性价比的算法](/airport/cost-performance/)选套餐更合适。

如果你的实时需求主要是视频会议、语音通话和长时间保持连接,那么优先级应该放在线路稳定性上,可以结合[专线的辨别与取舍](/airport/dedicated-line/)一起判断。

## 接下来怎么做

先用上面的自测流程跑一遍现有服务:如果晚高峰劣化不明显、抖动可控,那么问题多半不在机场,继续换服务不会改善。如果劣化幅度明显,再按线路类型和地区两个维度筛选候选,并且务必用月付验证一轮实际场景,再决定是否长期使用。
