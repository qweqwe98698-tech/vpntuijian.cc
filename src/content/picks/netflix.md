## 先把三个混在一起的问题拆开

关于 Netflix 的讨论里,最常被搅在一起的是三件不同的事:能不能登录、能看到多少内容、看得清不清楚。它们由完全不同的机制决定,却经常被笼统地说成「能不能解锁」。

能不能登录,取决于网络是否通,以及出口 IP 是否被彻底拒绝。能看到多少内容,取决于两层:出口 IP 有没有被归类为代理,以及落地地区的目录里有什么。看得清不清楚,取决于持续带宽,和前面两层没有关系。

其中最容易被误判的是中间那层。很多人发现自己「能打开、能播,但想看的剧都找不到」,以为是节点不好,实际上可能是两种完全不同的原因:要么出口被识别导致第三方版权内容不再提供,要么这个地区的目录里本来就没有那部作品。这两种情况的解法不同——前者要换节点,后者要换地区。

## 完整片库和只剩自制剧,差在哪里

平台自制内容的版权在全球统一,即使识别到代理仍然会放行;而采购来的第三方内容受地区协议约束,一旦判定为代理访问,就不再提供。所以「只能看自制剧」是一个非常明确的信号,它说明这个出口 IP 已经进了代理名单,只是还没有被完全拒绝。

| 现象 | 说明什么 | 该做什么 |
| --- | --- | --- |
| 完整目录,内容与该地区一致 | 出口未被归类为代理 | 记录这个节点,固定使用 |
| 只能播放平台自制内容 | 出口已被识别,属于部分解锁 | 换同地区其他节点重试 |
| 提示检测到代理,无法播放 | 出口已被明确拒绝 | 换节点,同组全部如此则换服务 |
| 能播但找不到目标作品 | 该地区目录本来就没有 | 换地区,不是节点问题 |
| 能播但画质持续降档 | 带宽或链路不稳 | 按带宽和拥堵方向排查 |
| 网页正常,App 异常 | 设备端解析或地区设置不一致 | 检查 DNS 与客户端规则 |

判断顺序应该是:先看能不能打开,再看目录完整度,最后才看画质。跳过中间那步,很容易把「地区没有这部剧」误判成「节点不能解锁」。

## 下单之前按这个顺序试

1. 先确定片单和地区。列出想看的三到五部作品,查清它们在哪些地区上架,再决定需要哪个地区的节点。
2. 选可以随时停的方案。用[短周期或试用方案](/airport/free-trial/)验证,不要为不确定的结果先付长约。
3. 核对真实出口地区。连接后查询实际出口国家,节点名称的标注不一定等于真实落地。
4. 检查目录完整度。用自己的账号搜索几部非自制的第三方作品,能搜到并正常播放,才算完整。
5. 锁定高清晰度试播。手动选最高画质连续播十分钟以上,观察是否降档或缓冲。
6. 覆盖晚高峰。白天流畅不代表晚上流畅,跨境线路在高峰期的差别很大。
7. 多端交叉验证。至少在浏览器和常用 App 各测一次,两端结果不同时先查 DNS 和分流规则。

## 为什么状态经常反复

平台持续更新用于识别代理的 IP 数据源,服务商也在持续更换落地机房和 IP 段。两边都在动,所以任何具体结论都只在某个时间点成立。一个节点从完整片库掉到只剩自制剧,通常不是因为你做了什么,而是它所在的 IP 段被重新归类了。

由此产生的实际建议是:不要把预期建立在「找到一个永久可用的节点」上。合理的做法是保留两三个备选节点、选择可以随时更换的付费周期,并接受隔一段时间要重新验证一次。评估一家服务时,失效后多快恢复、是否主动说明状态,比它此刻的表现更能说明问题。这也是本站不提供固定可用名单的原因:一份过期的名单会直接把人引向错误的判断。

## 看不了的时候怎么定位

先排除全局问题:如果所有网站都打不开,那是链路或订阅层面的故障,和平台判定无关。能正常上网只有视频异常,才进入下面的排查。

画面卡顿、清晰度反复降档,通常是带宽和拥堵造成的,集中出现在晚上的话可以参考[高峰时段变慢的处理](/troubleshooting/evening-peak-slow/)。同一节点在电脑和手机上表现不同,先比对两端的出口 IP 和解析结果,[域名解析异常](/troubleshooting/dns-resolution-failure/)是这类差异的常见来源。只有部分节点出现代理提示,大概率是这些落地被标记,按[部分节点异常](/troubleshooting/partial-nodes-fail/)处理。

如果你同时还要照顾其他视频平台,各平台的判定逻辑并不通用,可以先看[多平台解锁的整体思路](/airport/streaming/),再回到具体平台逐个验证;节点筛选的操作细节则可以参考[流媒体节点选择](/scenarios/streaming-node-guide/)。
