常规的系统代理只对"遵守代理设置"的程序生效,浏览器会走,但许多桌面软件、命令行工具和游戏会无视它。TUN 模式的做法更彻底:客户端创建一块虚拟网卡(TUN 设备),并修改系统路由,让所有流量先进入这块网卡,再由客户端按[分流规则](/glossary/rule-based-routing/)处理。对应用程序而言,代理变得完全透明。

使用语境上,TUN 模式常用于三类需求:让不支持代理的应用(如部分办公软件、游戏启动器)走代理;在客户端内统一处理 DNS,缓解 DNS 污染;排查"系统代理开了但某软件不走代理"的问题。[Clash](/glossary/clash/) 系、sing-box 等主流客户端均支持,在 Windows 上启用通常需要管理员权限,移动端的"VPN 模式"本质上是同类机制。

常见误解:一是把 TUN 模式等同于更快——它只是改变流量接管方式,不改变线路质量;二是认为开了 TUN 就万无一失——它与公司 VPN 客户端、虚拟机网络等争夺路由时可能互相冲突,表现为断网;三是忽略 DNS 配置——TUN 模式下 DNS 处理方式(如 fake-ip)配置不当,会出现"已连接但打不开网页"的现象,排查时应优先检查 DNS 设置。
