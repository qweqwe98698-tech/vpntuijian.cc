v2rayN 的排查有一个前提认知:**它只是一个图形界面**。真正建立连接的是它调用的底层内核程序。界面上显示「已连接」只说明配置被写入了,不代表内核真的跑起来了,也不代表连接成功。

所以排查的第一步永远是打开日志面板,而不是去改配置。日志里的信息量远超界面上的任何提示。

## 先分清三种失败形态

| 现象 | 日志表现 | 问题层级 |
| --- | --- | --- |
| 完全打不开网页,连接超时 | 日志无内核启动记录,或提示端口占用 | 内核未运行 |
| 网页打不开,但日志显示内核正常 | 无连接尝试记录 | 系统代理未生效 |
| 日志有连接尝试但报错 | 出现握手失败、认证错误等 | 配置参数不匹配 |

这三类的处理方式完全不同,搞错方向会浪费很多时间。

## 内核是否真的在运行

打开日志面板,查看是否有内核启动成功的记录。如果没有,或者看到红色错误:

1. **检查端口占用。** 最常见的报错就是本地监听端口被占用。如果你同时开着 Clash 或其他客户端,两者默认端口可能冲突。关闭其他客户端,或在 v2rayN 的参数设置里换一个端口。改完必须重启内核才生效。

2. **确认内核文件完整。** v2rayN 依赖的内核文件如果缺失或被安全软件隔离,启动会直接失败。检查安装目录下内核文件是否存在,以及杀毒软件的隔离区里有没有它。这是 Windows 上非常常见的一种情况——内核程序容易被误判。

3. **以管理员权限运行试试。** 部分系统环境下,写入配置文件或修改系统代理需要更高权限。

4. **检查安装路径。** 路径中包含中文或特殊字符时,少数版本的内核会启动失败。把程序移到一个纯英文路径下再试。

## 系统代理是否生效

内核正常运行但网页仍打不开,重点看代理是如何被应用到系统的。

v2rayN 有几种工作模式,常见的是「系统代理」模式和 [TUN 模式](/glossary/tun-mode/)。系统代理模式下,它会修改 Windows 的网络代理设置,让支持代理的程序把流量发到本地端口。这里有两个常见问题:

- **系统代理开关没打开。** 界面上要确认代理模式已经设置为自动配置或全局模式,而不是「清除系统代理」。
- **浏览器使用了独立代理设置。** 部分浏览器或浏览器插件(尤其是代理管理类扩展)会覆盖系统设置。如果装了这类扩展,把它设为「使用系统代理」或直接停用测试。

验证系统代理是否生效的方法:打开 Windows 设置里的网络代理页面,看是否显示了一个指向本地地址的代理服务器,端口号与 v2rayN 的设置一致。

## 配置参数是否匹配

日志里出现连接尝试但失败,说明前两层都通了,问题在配置本身。手动录入的节点最容易出这类错误:

- **传输方式不一致。** 服务端用的是 WebSocket 还是其他方式,客户端必须完全对应。
- **TLS 设置错误。** 是否启用 TLS、SNI 填什么、是否跳过证书验证,任何一项不对都会导致握手失败。
- **路径填错。** WebSocket 路径包括开头的斜杠在内,必须与服务端完全一致,多一个字符都不行。
- **UUID 或密码有误。** 复制时带入了空格或换行是常见问题。

如果节点是通过[订阅链接](/glossary/subscription-link/)导入的,这些参数由服务端下发,一般不会错。这种情况下先确认订阅是否更新成功,方法见[订阅链接更新失败的排查](/troubleshooting/subscription-update-failed/)。

还有一个容易忽略的点:**系统时间**。基于 TLS 的协议在握手时会校验证书有效期,本机时间偏差超过一两分钟就会全部失败。在 Windows 的日期时间设置里打开自动同步,然后手动点一次「立即同步」。

## 安全软件与防火墙

Windows 上这一项的干扰比其他平台都常见。表现通常是:内核启动了,配置也对,但连接就是建立不起来,或者时通时不通。

处理方式是把 v2rayN 的主程序和内核程序都加入防火墙的允许列表,以及杀毒软件的白名单。企业环境的电脑还可能有集中管理的安全策略,这种情况下本地无法绕过,需要联系管理员。

临时验证方法:短暂关闭第三方安全软件后测试。如果立刻恢复正常,就能确认是拦截问题,再去做白名单配置。注意测试后要把安全软件重新打开。

## 规则配置导致的部分不可用

如果是「有些网站能开,有些不能」,那不是连接问题,而是分流规则的问题。v2rayN 的路由设置里定义了哪些流量走代理、哪些直连。默认规则通常把国内域名和 IP 直连,境外走代理。

当某个网站被错误地归入直连,它就会打不开。这类情况的判断和处理见[分流规则](/glossary/rule-based-routing/)相关说明,以及[只有部分节点能连接是什么原因](/troubleshooting/partial-nodes-fail/)。

## 怎么确认已经恢复

按这个顺序验证:

1. 日志面板里有内核启动成功的记录;
2. 节点延迟测试能返回具体数值;
3. 浏览器能打开一个需要代理的网站;
4. 关闭代理后该网站打不开(确认流量确实走了代理,而不是本来就能访问)。

第四步经常被跳过,但它能避免一种误判:你以为代理生效了,其实是网站本身可以直连。

## 仍未解决时收集这些信息

- v2rayN 的版本号和内核版本;
- 日志面板中失败时刻的完整报错文本;
- 节点的协议类型和传输方式;
- 同一节点在手机端的测试结果;
- Windows 版本,以及是否使用第三方安全软件;
- 是否在公司或校园网络环境下。

如果手机端同一节点正常而电脑不行,不用联系机场客服,问题一定在本地。可以对照 [v2rayN 安装与配置入门](/clients/v2rayn-windows-guide/)重新走一遍配置流程,或者换用 Clash 系客户端交叉验证——两个客户端都失败才说明是服务端或网络环境的问题。
