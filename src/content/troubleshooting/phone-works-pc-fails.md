同一个订阅、同一份节点列表,手机上刷视频毫无压力,换到电脑上就连不上。遇到这种情况其实是好事——你手上已经有了一次现成的对照实验,手机和电脑共用了账号、订阅和服务端,唯一的变量是电脑本机的环境。

## 这个对照帮你排除了什么

手机能正常使用,意味着下面这些因素统统可以先放到一边:

- 账号没有到期,流量没有用尽,也没有触发风控;
- 订阅内容正常下发,节点配置本身有效;
- 机场服务端在线,你所在地区到该节点的线路是通的。

剩下需要怀疑的,只有电脑上的这几层:客户端有没有真的接管流量、本机有没有软件在拦截、DNS 和 IPv6 的处理是否和手机不同、以及有没有旧配置残留。

## 三条岔路,先走对方向

打开电脑上的浏览器,访问一个需要代理的网站,再访问一个国内网站,把结果对照下表:

| 现象 | 可能原因 | 对应处理 |
| --- | --- | --- |
| 两类网站都打不开 | 电脑本身没网,或代理接管后把所有流量都吞掉了 | 先关闭代理测试国内网站,确认基础联网 |
| 国内网站正常,境外网站超时 | 系统代理未生效,或规则把目标域名放进了直连 | 检查代理开关与分流规则 |
| 客户端显示已连接,浏览器一直转圈 | 流量进了客户端但出不去,多为 DNS 或出站配置问题 | 参考[显示已连接却打不开网页](/troubleshooting/connected-but-no-internet/)的处理思路 |
| 只有个别网站不通 | 规则或节点的落地限制 | 换节点对照,不必怀疑整套配置 |

先把自己的现象归到某一行,后面的步骤才有针对性。

## 按网络层往下走

**第一层,基础联网。** 完全退出代理客户端,直接访问国内网站。这一步失败就和代理无关了,去处理网卡、路由器或宽带本身。

**第二层,系统时间。** 电脑长期休眠或者双系统切换后,时间偏差几分钟就足以让加密握手失败。手机通常自动校时更准,这正是两台设备表现不同的一个隐蔽来源。把时间设为自动同步后重启客户端。

**第三层,代理是否真的生效。** 这是电脑端最高频的故障点。客户端窗口里的开关打开,不等于系统层面已经接管:

- 用系统代理模式时,要确认操作系统的代理设置里确实写入了本地地址和端口;
- 用虚拟网卡([TUN 模式](/glossary/tun-mode/))时,要确认虚拟网卡已经创建并且拿到了管理员权限;
- 某些浏览器有自己的代理设置或内置的加速功能,会绕开系统代理,需要单独关闭。

**第四层,订阅与节点状态。** 手机上正常不代表电脑上的订阅是最新的。手动更新一次订阅,看节点数量是否和手机一致;数量对不上,说明电脑上用的是旧配置。

**第五层,DNS。** 电脑上的 DNS 往往被路由器、公司网络或以前装过的加速工具改过。如果域名解析到了错误地址,连接就无从谈起,具体判断方式见 [DNS 解析异常的排查](/troubleshooting/dns-resolution-failure/)。

**第六层,IPv6。** 家庭宽带在电脑上启用双栈的情况很常见,而部分节点只有 IPv4 出口。在客户端里把 IP 版本策略改成优先 IPv4 再测一次。

**第七层,分流规则。** 电脑端客户端的规则集通常比手机端复杂。检查是否有规则把你要访问的域名或整个网段划进了直连。

**第八层,防火墙与安全软件。** 放到这一层是因为它需要临时改动系统状态,不适合一开始就动。测试完记得恢复原设置。

## Windows 上容易踩的坑

Windows 的问题大多集中在权限和残留配置上。

安全软件是头号嫌疑。国内几款主流安全软件会把创建虚拟网卡、修改系统代理的行为判定为可疑操作,有时候会静默拦截而不弹窗提示。临时退出后重试,是最快的验证方式。

其次是残留的代理设置。以前用过的工具异常退出后,可能在系统的「Internet 选项」里留下一个已经没人监听的代理地址,导致所有请求发到一个死端口。表现就是无论开不开客户端,网页都打不开。

还有一类是客户端本身没有以管理员身份运行,导致虚拟网卡创建失败但界面上看不出来。具体到常见客户端的配置细节,可以对照 [v2rayN 在 Windows 上的配置说明](/clients/v2rayn-windows-guide/);如果你用的就是这个客户端并且卡在连接环节,还有一篇更专项的 [v2rayN 连不上的排查](/troubleshooting/v2rayn-cannot-connect/)。

## macOS 上容易踩的坑

macOS 的问题更多出在授权和网络位置上。

首次启用虚拟网卡或安装网络扩展时,系统会弹出授权请求。这个弹窗如果被忽略或误点了拒绝,客户端会处于「开着但没接管任何流量」的状态,而界面上往往只显示已连接。到系统设置的隐私与安全性里检查是否有待批准的项目。

网络位置是另一个容易被忘记的地方。如果曾经为不同场景创建过多个网络位置,某个位置里可能保存着旧的代理配置。切回自动模式再测试。

另外,macOS 上的部分应用会缓存 DNS 结果,改完 DNS 配置后建议重启浏览器,而不只是刷新页面。

## 怎么确认真的恢复了

不要只看客户端里的延迟数值。可靠的做法是这样:先打开一个需要代理的网页确认完整加载,再打开一个国内网站确认没有被误导流,最后断开代理刷新一次,确认境外站点变回打不开的状态。三步都符合预期,才说明流量确实按你的设想在走。

## 还是不行的时候准备这些材料

如果上面的步骤都走完了仍然没有恢复,在找客服或者向别人求助之前,先把这些信息整理好:

- 电脑的操作系统版本、客户端名称和版本号;
- 手机上正常使用的截图或说明,用来佐证账号本身没问题;
- 电脑上具体的失败表现,以及客户端日志里失败时刻的那几行;
- 电脑连手机热点时的测试结果,这一项能直接区分本机问题和线路问题;
- 是否安装过其他代理或加速工具,以及是否已经完全卸载。

准备这几项,通常比反复描述「就是用不了」要有效得多。
