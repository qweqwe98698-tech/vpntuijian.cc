「导入失败」和「更新失败」这两个说法在群里经常被混着用,但它们是两码事,处理方向也完全相反。分不清这一点,很容易在错误的方向上折腾很久。

## 先把两种失败分开

判断标准只有一个:客户端有没有把内容拿到手。

| 你看到的报错 | 实际含义 | 该看哪篇 |
| --- | --- | --- |
| 连接超时、请求失败、无法访问 | 内容根本没下载下来,卡在网络请求这一步 | [订阅更新失败的处理](/troubleshooting/subscription-update-failed/) |
| 解析错误、格式无效、配置不合法、YAML 错误 | 内容拿到了,但客户端读不懂 | 本文 |
| 提示成功但节点数为零 | 内容拿到了,能读懂,但里面没有有效节点 | 本文最后一节 |

换句话说,更新失败是「路不通」,导入失败是「话听不懂」。本文只讲后者。

## 格式不匹配是怎么发生的

代理客户端不是只有一种。不同客户端底层用的内核不同,能识别的配置写法也不同:有的读 YAML 结构的配置,有的读 Base64 编码的节点列表,有的读 JSON。机场为了兼容这些客户端,通常会在后台生成好几条订阅链接,或者用链接末尾的参数来控制返回什么格式。

于是最典型的错误就出现了:随手复制了页面上第一条链接,粘进一个内核完全不同的客户端,服务端老老实实返回了内容,客户端却一个字都读不懂,直接抛出解析错误。

这里有一个很实用的判断方法:把[订阅链接](/glossary/subscription-link/)粘到浏览器里打开看一眼返回的内容。如果是一大段结构清晰、带缩进和中文节点名的文本,那是 YAML 类配置;如果是一整片没有换行的乱码字母,那是 Base64 编码的节点列表。再对照你的客户端需要哪一种,匹配不上就是问题所在。

## 常见客户端认哪种格式

| 客户端类型 | 通常需要的订阅格式 | 后台链接上的常见标识 |
| --- | --- | --- |
| Clash 系客户端 | YAML 结构的配置文件 | 标注 Clash,或参数含 clash |
| Shadowrocket 等移动端 | 通用 Base64 节点列表 | 标注通用订阅、或 v2ray/ss |
| sing-box 系客户端 | JSON 配置 | 标注 sing-box 或 singbox |
| 支持多内核的桌面客户端 | 视当前选择的内核而定 | 需要先确认客户端正在用哪个内核 |

这张表只是大方向,具体以机场后台的说明为准。各家机场的命名习惯差别不小,同样是「通用订阅」,含义可能并不一致。

## 排除掉几个低级但高频的原因

在动格式之前,先把这几项过一遍,它们造成的报错和格式问题长得很像:

**链接本身被复制坏了。** 从聊天软件或网页复制时,容易带上前后的空格、换行,或者被输入法替换成了中文冒号。粘贴后检查开头是不是完整的 http 或 https,结尾有没有多出来的字符。

**链接被截断。** 订阅链接通常很长,在窄屏幕上显示时可能只选中了一部分。用后台提供的复制按钮,而不是手动拖选。

**客户端版本太旧。** 订阅里如果包含较新的协议类型,老版本客户端识别不了,轻则跳过部分节点,重则整份配置解析失败。先升级客户端再判断。

**导入位置放错了。** 有些客户端区分「添加订阅」和「添加单个节点」两个入口,把订阅链接粘到单节点入口里,必然报格式错误。

**机场返回的是一个错误页面。** 账号异常或链接失效时,部分机场返回的是 HTML 页面而不是配置内容,客户端拿到 HTML 自然解析不了,报的却是格式错误。这种情况在浏览器里打开链接就能一眼看出来。

## 按顺序把订阅导进去

1. 登录机场后台,找到订阅区域,确认当前账号状态正常、套餐没有过期。
2. 在多条链接里找到与你的客户端对应的那一条,用复制按钮复制。
3. 回到客户端,删掉之前导入失败的那条残留记录,不要在失败的条目上反复点更新。
4. 通过「添加订阅」入口粘贴,粘贴后先检查一遍地址完整性再确认。
5. 等待首次拉取完成,查看节点数量是否与后台一致。
6. 随机选一个节点做连通性测试,确认能返回具体延迟数值。

各客户端的具体操作路径不一样,详细步骤可以看 [Clash 导入订阅的完整流程](/clients/clash-subscription-import/)、[Shadowrocket 的导入方式](/clients/shadowrocket-subscription-import/),或者 [sing-box 的上手说明](/clients/sing-box-getting-started/)。

## 导入成功但一个节点都没有

这种情况说明格式其实是对的,客户端也读懂了,只是内容里没有可用节点。按可能性从高到低排查:

- **套餐到期或流量耗尽。** 不少机场在这两种状态下会返回一份空的节点列表,而不是报错。登录后台看剩余时间和流量。
- **订阅链接被重置。** 后台点过重置后,旧链接会立即失效,有的机场返回空内容而非错误。重新复制新链接。
- **格式参数不完整。** 链接虽然能解析,但缺少指定客户端类型的参数,服务端按默认规则返回了一份不含节点的骨架配置。
- **筛选条件把节点全过滤掉了。** 部分客户端支持按关键词过滤节点,如果之前设置过过滤规则,可能全部节点都被排除。检查客户端里的节点过滤设置。

## 怎么算真的导入成功

三个标志同时满足才算数:节点数量与后台显示一致;配置的更新时间是刚才那一刻;任选一个节点连上后能打开需要代理的网页。只满足前两项,只能说明配置读进来了,不代表能用。

## 仍未解决时提供这些信息

联系客服时,把下面几项一次说清楚,比来回追问快得多:

- 客户端名称、版本号和所在系统;
- 你复制的是后台哪一条链接(描述链接旁边的文字标注即可);
- 客户端给出的完整报错文本,原样复制,不要转述;
- 在浏览器里直接打开该链接看到的内容类型(乱码文本 / 结构化文本 / 错误页面);
- 是否换过其他客户端测试,结果如何。

最后提醒一句:订阅链接里带着你的账号凭据。截图求助前先把链接中的密钥部分遮掉,也不要把完整链接贴进公开群组。
